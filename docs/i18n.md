# Translating the client

English is the source of truth. Every other language is measured against it, and a key missing from a translation falls back to English rather than showing the raw key to a user.

## Layout

```
apps/web/src/i18n/
├── resources.ts          registered languages and bundles
├── index.ts              i18next setup
└── locales/
    ├── en/               ← the source of truth
    │   ├── common.json     shared words: actions, states, connection, presence
    │   ├── auth.json       sign-in screen
    │   ├── rooms.json      sidebar, room header, room info
    │   ├── messages.json   the timeline, message actions, system messages
    │   ├── composer.json   message box and attachments
    │   ├── media.json      the media viewer
    │   └── settings.json   appearance and language
    ├── ja/
    └── vi/
```

Namespaces mirror the feature folders, so translating the composer means opening exactly one file and never guessing where a string lives.

## Adding a language

1. Copy `locales/en` to `locales/<code>` using the [ISO 639-1 code](https://en.wikipedia.org/wiki/List_of_ISO_639_language_codes) (`fr`, `ja`, `pt-BR`).
2. Translate the values. Leave the keys alone.
3. Register it in `resources.ts` — import the files, add the bundle, and add an entry to `LOCALES`:

```ts
{ code: 'fr', name: 'Français', englishName: 'French' }
```

`name` is written in the language itself, because that is what people scan for in a language picker. `englishName` is the label everyone else can read.

4. Run the checks:

```bash
pnpm --filter @open-rocket-chat/web test
```

## What the checks enforce

`src/i18n/__tests__/locales.test.ts` compares every language against English and fails on:

- **A missing key.** The string would silently fall back to English.
- **An extra key.** Usually a rename that was not carried across; it would sit unused and untranslated forever.
- **Placeholder drift.** If English says `{{name}} joined the channel` and the translation drops `{{name}}`, the sentence loses its subject. The check compares the placeholder set of every string.
- **An empty value.** An empty string is not a fallback — it renders as nothing.

## Things worth knowing

**Placeholders** are `{{name}}`. Keep the spelling exactly; you may move them anywhere in the sentence.

**Plurals** use i18next suffixes. English needs two forms:

```json
{ "members_one": "{{count}} member", "members_other": "{{count}} members" }
```

Your language may need one, or six. The tests compare base keys, so Vietnamese carrying only `members_other` is correct and passes — it is not required to invent a distinction its grammar does not make.

**Line breaks** are written as `\n` inside the JSON string; the components that need them render with `white-space: pre-line`.

**Don't translate**: `appName`, and the unit labels in `common.fileSize` (`KB`, `MB`). File sizes are read as technical values, and translating the units invites drift between the two places the same file is shown.

**Length matters.** The sidebar and message actions are tight. If a translation is much longer than the English, check it in the app before opening the pull request — a truncated label is worse than a slightly awkward shorter one.

## Reviewing your work in the app

Switch language in **Settings → Language**. The choice is stored in `localStorage` under `orc:locale`, and on a fresh visit the browser's language is detected automatically.

## Fixing an English string

English is also where wording bugs get fixed. Change `locales/en`, then update every other language — or say in the pull request which ones you could not, so someone else can pick them up. The tests will fail until they all match, which is the point.
